# Security — implemented controls and verification

This is a public content site with no server runtime, no database, no accounts, and no visitor data — but it ingests third-party XML and renders third-party HTML, so its security posture is real and specific. This document lists what is actually implemented and what was actually checked; it does not claim a penetration test or any certification.

## Threat surface

1. **Feed ingestion** (`scripts/sync.ts` → `src/lib/server/extract/`): third-party XML and CDATA HTML, fetched at build/refresh time.
2. **Rendering** of that ingested content into static HTML.
3. **The static output itself**: headers, CSP, external links and media.
4. **The build pipeline**: environment, dependencies.

## Implemented controls

**Feed ingestion**

- The feed URL is a single allowlisted constant (`src/lib/server/config.ts`); no request input can ever steer a fetch (no SSRF surface). `--input <file>` exists for offline/test runs.
- The fetch is bounded: 30 s timeout, 25 MB cap on declared and actual body size, redirect chain must land on the allowlisted host.
- The XML parser runs with entity resolution **off** (`processEntities: false`, `htmlEntities: false`): internal entities stay literal and external entities throw — XXE and entity-expansion are removed as failure classes, not mitigated. Pinned by `tests/unit/feed-parser.test.ts`.
- Numeric character references inside descriptions are decoded exactly once, at the read boundary (`feed.ts`), and only into plain text — the downstream rebuild re-escapes, so decoding cannot resurrect markup.

**Content rendering**

- All feed HTML passes through `sanitize-html` with a narrow allowlist (`p, br, a, strong, em, b, i, ul, ol, li, blockquote`; `href` only, `https:`/`mailto:` only) and a strip-never-blank rule for unsafe schemes. Every surviving link is forced to `rel="noopener noreferrer" target="_blank"` — and the attribute allowlist lists `rel`/`target` so the transform's values actually survive (a defect the tests caught; see `tests/unit/sanitize.test.ts`).
- URLs are validated by shape and host at ingestion: enclosures must be `https` on `sphinx.acast.com` with the `/p/open/s/<show>/e/<id>/media.mp3` path; item links only on the Acast/YouTube host list; sponsor links reject the show's own hub and the legacy redirectors; images only on `assets.pippa.io`. Nothing validates media by fetching it, and `HEAD` is never used (the source returns a misleading 200).
- The store itself is re-validated with zod on **every read** (loaders and the build), so a hand-corrupted JSON file fails loudly instead of rendering.

**Browser and transport**

- Content Security Policy generated by SvelteKit's `kit.csp` in hash mode (`vite.config.ts`): `script-src 'self'` plus SvelteKit's own inline-bootstrap hashes — strict scripts, and the earlier static-tag variant that silently broke hydration is gone. `style-src` allows runtime custom properties the signature interaction and the seek fill need. `img-src` and `media-src` are allowlisted to the verified Acast hosts; `frame-src 'none'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'none'`, `default-src 'self'`, `connect-src 'self'`.
- No `on*` event-handler attributes exist in any built page (verified by build-output grep and zero CSP console violations in the browser checks) — the reveal effect and player bindings attach real listeners.
- No third-party scripts, fonts, analytics, or embeds. YouTube is linked out, never embedded. Fonts are self-hosted from OFL packages.
- Nothing autoplays; the audio element is created with `preload="none"` and only the visitor's press starts a fetch.

**Data and privacy**

- No visitor accounts, forms, cookies, analytics, or storage. Nothing about a visitor is collected, so there is nothing to leak, and there is no admin surface to protect in this cut.
- No secrets in the repository: one optional, non-secret environment variable (`PUBLIC_ORIGIN`, an https origin for canonical URLs); `.env.example` documents it. Secret scans of the working tree have found none.

## Host-deployed headers (not expressible in a meta tag)

The CSP ships as a meta tag (prerendered static pages), so these must be set by the host and are part of the deployment contract (`docs/DEPLOYMENT.md`): `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, and CSP `frame-ancestors 'none'` (or equivalent clickjacking protection).

## Reporting

The repository is currently local and unpublished. When it is published, security reports go through the hosting platform's private vulnerability reporting for the repository owner; a dedicated contact will be added here once one exists. No user data is processed, so there is no breach-notification surface today.
